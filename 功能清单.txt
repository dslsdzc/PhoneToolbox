[√] SBC 修补 (preloader 字节模式, 参照 mtkclient 五模式) —— **已接线** (MTK 刷写流程显式选项,
    默认关 + Tier 3 二次确认; 命中时点名模式, 未命中如实告警; 仅作用于本次 EMI/DRAM 初始化用的内存副本,
    不改写设备上的 preloader 分区)
[√] 刷写路由骨架 (runBromFlash: 枚举 → 会话 → 逐分区)
[√] DA 文件解析与选择: AllInOne 头/条目/region 5 字段 (真样本 6 文件 161 条目硬断言 + 独立 Python 解析器对拍)
[√] DA 两阶段: DA1 (region[1] 地址/长度/签名长度) → 0xC0 就绪 → 存储信息交换 → EMI/DRAM → DA2 (保留尾部签名) → read_flash_info
[√] DA 切分另存: 选中条目的 DA1/DA2 逐字节落盘为 da1.bin / da2.bin (保留 da2 尾部签名 —— 剥签名属协议层;
    同名覆盖; 失败不留半份产物; 只碰本地文件系统, 不发一个字节给设备)
    (W8-T6 起 UI 入口已接: 刷机面板「导出 DA 片段…」= 显式输入 **DA 文件 + 芯片码 hw_code**,

[√] EMI/DRAM 初始化: LEGACY 逐版本档位 (0x00/0x0A/0x0B/0x0C/0x0D/0x0F/0x10/0x11/0x14/0x15) + M_EXT_RAM_* 回包判定
    (含两处比上游更严的 fail-closed: EMI 应答非 ACK/NACK / 档 C/D 的 dramlength 超长; 见 mtk-brom-facts.md §4.2 附注)
[√] preloader 两路径: 显式指定 / 固件目录自动导入 (唯一命中才用) / 网络获取 (**默认关闭**, 来源清单 + sha256 校验, fail-closed)

--- MTK BROM 漏洞利用 (W8, kamakiri 路径; 自研, 行为对照 bkerler/mtkclient 源码逐条核实) ---
[√] 载荷修正 (纯函数): 尾 4 字节 0x10007000 → 该芯片 watchdog / 尾 8..4 字节 0x11002000 → uart;
    长度补齐 4 字节对齐; 非命中分支**如实记日志**(不静默); 地址一律经"带存在位的取用口"取
    (**直接读值槽会把 0 写成 watchdog —— 砖机路径**)
[√] 逐芯片硬件地址: 上游 hwconfig 的 7 字段 (watchdog/uart/brom·da·plPayloadAddr/cqdmaBase/sejBase)
    + W8-T3 补的 var1 (第 8 字段) 全表转写, **存在位是一等公民** (缺 = 响亮拒绝, 不猜 0)
[√] 载荷来源解析: 显式文件优先 → 内容寻址缓存 → 来源清单 (逐芯片条目优先, 通用兜底);
    **网络默认关闭** (关闭时下载器一次都不会被调用); 下载字节一律 **sha256 fail-closed** 才采用;
    清单只存 URL + sha256 (**本仓不分发任何利用载荷二进制**)
[√] kamakiri 编排: 触发控制传输 (wIndex = 表里的 var1) + priming 读 + 载荷上传/触发;
    **失败即响亮中止**(上游把触发失败吞掉后照样报成功 —— 不复刻); 成功判据 = 载荷回 **ack 0xA1A2A3A4**
[√] 前置判据(离线可判): 芯片未收录 / IoT / 已修补代际(V6, 默认早退, opt-in 才硬闯) / 缺三要素 →
    明确拒绝, 且都在任何设备 I/O **之前**判 (不碰设备就报错)
[√] UI 接线 (W8-T6): 漏洞面板新增「MTK BROM 漏洞利用」区 —— 目标芯片 hw_code / 载荷来源
    (文件或显式开启的网络获取) + 「解析载荷」/「执行利用」/ 逐步日志;
    执行前过 **Tier 3 二次确认** (与扫描/利用同一档同一闸门);
    按钮禁用时给出**可行动原因** (未选设备 / 芯片不在表内 / IoT / 缺三要素 / 载荷未解析 / sha256 不过)
[√] DA 切分另存的 UI 入口 (W8-T6): 刷机面板「导出 DA 片段…」—— 显式输入 DA 文件 + 芯片码 hw_code,
    **不依赖连接设备** (dacode 由芯片表给出); 本地只读 ⇒ **不纳门控** (W2 界线: 改设备状态才弹);
    不做"按序号挑条目"入口 (按 entryRegionIndex 取会把 region[0] 的 EMI/env 当 DA1)
[√] 诚实边界: **真机全链未验证 (无 MTK 真机)** —— 判据/载荷解析/修正/DA 另存可离线完整验证,
    编排层只有"编译 + mock 通道"级证据; UI 层按钮状态机与执行前的握手有 offscreen 用例,
    但**生产执行器** (枚举 USB/握手/读设备芯片码/触发) **无自动化覆盖**;
    已修补代际判据是**粗判据** (来自公开报告, 非逐设备实测, 会有假阳性);
    var1 覆盖口**未暴露到 UI** (缺 var1 的芯片由编排层响亮失败)

--- MTK BROM XFlash/XML 两代 (Phase D2+D3, 2026-09-16) ---
[√] XFlash 帧层: 12B 小端帧 (magic/datatype/len, 头一次写+载荷分块) + status 三态判据 + ack 的 0x6781 特例 (16B 单写)
[√] XFlash 引导: 七步握手 (SYNC → SETUP_ENV → SETUP_HW_INIT → 读回 SYNC; **SYNC 只发不读**) + bring-up 四步 (expire_date/reset_key/checksum_level/connection_agent; 有回包的查询都带**尾部 status**, 分区表类别是唯一例外)
[√] XFlash EMI: INIT_EXT_RAM + **长度单独一帧** + 0x200 分块 (整块切片 912B, 与 LEGACY 800B 并存; 832 真样本两代对拍 832/832)
[√] XFlash DA2: BOOT_TO **剥尾部签名** + sleep + status ∈ {0, SYNC} —— 成功 = 状态字匹配, **不证明 DA2 在跑** (日志只写"已上传")
[√] XFlash 写读: WRITE_DATA **56B 参数** (8×u32 NandExtension) + write_packet_length 分块 (非 512 对齐 → fail-closed) + 循环后最终 status + CC_OPTIONAL_DOWNLOAD_ACT; READ_DATA 逐帧收数 + flag 判定
[√] GPT 分区表: 512/4096 扇区探测 + 头/条目**双 CRC fail-closed** + 备份 GPT 窗口兜底 (真 4096 样本 PGPT/SGPT; sgdisk 输出仅作分区名集合旁证, **非逐条对拍基准**; 上游 4 处缺陷不复刻)
[√] XFlash 链整合: GET_PACKET_LENGTH/GET_CHIP_ID/GET_PARTITION_CATA → GPT 读 → 逐分区 WRITE_DATA (地址取分区条目 first_lba) → SHUTDOWN 收尾; PMT 分支**明确拒绝** (上游不可达且有 bug)
[√] XML 帧层: 文本帧 (str 长度 = 字符数+1 且带 NUL) + OK / OK@0x<hexlen> / OK!EOT 保活 + command_result 解析 + DA 日志帧**跳过** (有上限) + `ERR!` 一律判失败 (不复刻上游把它当成功)
[√] XML 引导: 等 **CMD:START** 文本消息 + setup_env (`initialize_dram=YES`, **不发 EMI**) / setup_hw_init / SET-HOST-INFO; 三步各自点名失败
[√] XML 写读: WRITE-FLASH (FileSysOp key=FILE-SIZE → ackValue(length) ×2 → 逐包 ack/数据) / READ-FLASH (**逐帧 ack** 的 download_raw 形状, 独立于单次尾 ack 分支) / REBOOT 收尾
[√] XML 链整合: CMD:START 引导 + READ-FLASH 读 GPT (与 XFlash/LEGACY 共用同一解析器) + 逐分区 WRITE-FLASH (写地址 = 分区条目 first_lba, 存储描述符 "EMMC-USER") + REBOOT 收尾
[√] 刷机通道文案: 日志/按钮提示写明按设备代际自动选链 (LEGACY / XFLASH / XML)
[√] 诚实边界: **真机全链未验证 (三代都没有)**; XML 侧**无真实设备样本** (帧与命令全部来自上游代码); GPT 样本来自第三方仓库 (MPL-2.0, 只读离线、不进构建); XFlash/XML 都只走**主 GPT** (diskSectors=0, 备份兜底不可用且如实说明); 存储只 eMMC user (0x1/0x8) —— 这是**编译期常量** (XFlash 走数值对, XML 走 "EMMC-USER" 文本), XFlash/XML 两条链**没有设备侧存储类型来源** (命令表无 GET_EMMC_INFO/GET_UFS_INFO), 故**不检测 UFS**: 真机 UFS 机型**不会被拦**, 写入按 eMMC 用户区偏移; 写出前的 fail-closed 门只在描述符被改成非 eMMC 时触发; 0x6781 的 16B ack 仅按上游实现 (无该芯片真机复核)
